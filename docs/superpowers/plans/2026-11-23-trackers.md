# Trackers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tap-to-log "trackers" (e.g. Tylenol). Each tap records a timestamped entry. An optional "Ask who" setting links the entry to a household member. Trackers have a Today card and a Trackers tab on Tasks.

**Architecture:**
- A new optional module, `trackers` (default on), with two tables.
- A route file guarded by `moduleRoutes('trackers')`.
- A web API client on the existing `bus.ts` refetch pattern.
- Two small design-system components: a person-pick modal and an undo toast.
- A Today card and a Tasks tab.

**Tech Stack:** Postgres 16 / node-pg-migrate SQL, lambda-api TypeScript, vitest + testcontainers, React 19 + vitest/RTL.

**Spec:** `docs/superpowers/specs/2026-11-23-trackers-design.md`

## Global Constraints

- **Module key:**
  - `trackers` is the module key, with `defaultOn: true` and `status: 'available'`.
  - It must be added to both catalogs (`apps/api/src/platform/modules.ts` and `apps/web/src/lib/modules.ts`, with matching name/icon/description).
  - Catalog values: name `Trackers`, icon `⏱️`, description `Tap-to-log items like a medicine dose — every tap is kept, and each shows when it last happened.`
- **Migration:**
  - The file is `apps/api/migrations/0108_trackers.sql`, with `-- Up Migration` / `-- Down Migration` sections.
  - Use the composite `(household_id, person_id)` FK pattern from `0104_persons_household_composite_fks.sql`.
  - `npm run check:migrations` must pass.
- **Module off:** every `/api/trackers*` and `/api/tracker-entries*` route returns **403** (that is `requireModule`'s behaviour).
- **Permissions:**
  - Any member can log, edit or delete entries.
  - Creating, updating or archiving a tracker requires `tenant.isAdmin || tenant.memberType === 'adult'`, otherwise 403.
- **"Ask who" enforcement:** when `ask_person` is true, `POST /api/trackers/:id/entries` without `personId` returns **422** `{ error: 'PersonRequired' }`.
- **Cross-household references:** a `personId` outside the household returns **400**, via `assertPersonInHousehold`, which throws `InvalidReferenceError`. Map it the same way `rhythms.routes.ts` does.
- **API JSON is camelCase:** `askPerson`, `occurredAt`, `personId`, `loggedBy`, `lastEntry`.
- **"Last time" copy:**
  - Format: `Last time: MM/DD h:mm AM/PM` in the **household timezone**, e.g. `Last time: 11/23 2:15 PM`.
  - When the entry has a person, append ` · <name>`.
  - With no entries, show `Not logged yet`.
- **No changes to the chores, rhythms or goals models, routes or screens.** The Tasks screen only gains a tab.
- **Code rules:** comments explain the why, max ~6 lines, and no backticks inside SQL in JS template literals. Reuse `Avatar`, `.modal-overlay` / `.modal-card`, `.field`, and `btn btn-primary`.
- **Changelog:** add an entry under `## [Unreleased]` → `### Added`, with a bold lead and a plain sentence.

## Review Focus

1. **Double tap on the kiosk.** Two quick taps produce two entries. That is intended, so the undo toast must undo only the last one, and must not throw if that entry was already deleted (404 → just dismiss).
2. **Timezone.** On a kiosk whose browser timezone differs from the household's, "Last time" uses the household timezone (Task 4 test).
3. **Archived trackers.**
   - They are hidden from the Today card and the default list, with no new entries allowed: 409 `{ error: 'Archived' }`.
   - Their history stays readable via `?includeArchived=1` (Task 2/3 tests).
4. **Deleted person.** `person_id` is set to null (Task 1 schema test). The history renders "Someone" rather than crashing (Task 7 test).
5. **Ask who turned on after entries exist.** Old entries with no person still render, and only new taps require a person (Task 3 test).

### Task 2: Tracker CRUD API

**Files:**
- Create: `apps/api/src/modules/trackers/trackers.ts` (service)
- Create: `apps/api/src/modules/trackers/trackers.routes.ts`
- Modify: `apps/api/src/app.ts` (import and call `registerTrackerRoutes(api)` next to `registerRhythmRoutes`)
- Test: `apps/api/test/trackers.integration.test.ts`

**Interfaces:**
- Produces this JSON type, used by Tasks 3 and 4:

```ts
interface TrackerDto {
  id: string; title: string; emoji: string | null; askPerson: boolean; sortOrder: number
  archivedAt: string | null
  lastEntry: { id: string; occurredAt: string; personId: string | null; personName: string | null } | null
}
```

- Routes:
  - `GET /api/trackers` (`?includeArchived=1` optional) → `{ trackers: TrackerDto[] }`, ordered by `sort_order, created_at`.
  - `POST /api/trackers` with `{ title, emoji?, askPerson? }` → 201 `{ tracker }`.
  - `PATCH /api/trackers/:id` with `{ title?, emoji?, askPerson?, sortOrder?, archived?: boolean }` → `{ tracker }`.
  - `DELETE /api/trackers/:id` → 204. This is a hard delete; entries cascade.
- `lastEntry` is computed with a `LEFT JOIN LATERAL` on `tracker_entries ... order by occurred_at desc limit 1`, joined to `persons` for `personName`.

**Interfaces:**
- Consumes `TrackerDto` from Task 2.
- Produces:
  - `EntryDto { id, trackerId, occurredAt, personId, personName, loggedBy, loggedByName, note }`.
  - `POST /api/trackers/:id/entries` with `{ personId?, occurredAt?, note? }` → 201 `{ entry }`. `logged_by` is set to `tenant.personId`.
  - `GET /api/trackers/:id/entries?personId=&before=&limit=` → `{ entries: EntryDto[], nextBefore: string | null }`.

  - `DELETE /api/tracker-entries/:id` → 204.
