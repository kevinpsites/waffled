# Mealie Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a household connects Mealie, its recipes, meal plan and shopping list come
live from Mealie through Waffled's API. The built-in recipe, meal and grocery screens swap
to Mealie-backed views.

**Architecture:**
- **Server:** a new `apps/api/src/modules/mealie/` module stores one encrypted connection
  per household. It proxies a fixed set of Mealie endpoints behind a per-household in-memory
  TTL cache, and maps Mealie errors to Waffled errors whose `name` is a stable code.
- **Web:** a `MealieProvider` context fetches the connection once. Pages and cards branch on
  `useMealie().connected` and render Mealie variants. Module gating is unchanged.

**Tech Stack:** lambda-api + TypeScript + Postgres 16 (node-pg-migrate), vitest +
testcontainers; React 19 / Vite PWA, vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-24-mealie-design.md`. Read it before any task. It
holds the Mealie endpoint table and all copy.

## Global Constraints

**Mealie**
- Mealie 2.0+ only. Reject `about.version` with major < 2 using 400 `"Mealie 2.0 or newer is
  required"`. Reject a token that Mealie answers 401 with 400 `"Mealie rejected that token"`.
- Outbound calls: global `fetch`, `AbortSignal.timeout(8000)`, header `Authorization: Bearer
  <token>`. Only fixed paths under the stored `base_url`, never a request-derived URL.

**Error mapping.** The `name` is the code; `app.ts` serializes it as `{error: name, message}`.

| Condition | Waffled error |
| --- | --- |
| Network failure or timeout | 502 `MealieUnavailable` |
| Mealie 401/403 on a read or write | 502 `MealieAuthFailed` |
| Mealie 404 | 404 |
| Mealie 422 | 400, with Mealie's `detail` or message |
| No connection | 409 `MealieNotConnected` |
| No shopping list chosen | 409 `MealieNoShoppingList` |

**The token**
- It never appears in any response body or log.
- It is stored via `encryptSecret` (`platform/crypto.ts`).
- If `encryptionAvailable()` is false, return 500 `"Encryption isn't configured on this
  server"`.

**Cache TTLs (ms)**

| Data | TTL |
| --- | --- |
| Meal plan | 30000 |
| Recipe search | 60000 |
| Recipe detail | 300000 |
| Shopping list | 10000 |

- A write clears that household's entries of the same kind.
- A connection change clears all entries for that household.

**Routes**
- Mealie routes are **not** behind `moduleRoutes`.
- Connection writes and shopping-list listing use `adminRoute`. Everything else uses
  `tenantRoute`. Both come from `platform/route-guards.ts`.

**Validation**
- Creatable `entryType` values: `breakfast`, `lunch`, `dinner`, `side`.
- Meal sort order: breakfast, lunch, dinner, side, then anything else, alphabetically.
- Mealplan range is at most 62 days. Recipe page size (perPage) is 24.
- Shopping item text is 1–200 characters after trimming.
- Image sizes map as follows, and `recipeId` must be a uuid.

  | `size` | Mealie file |
  | --- | --- |
  | `min` | `min-original.webp` |
  | `original` | `original.webp` |
  | `tiny` | `tiny-original.webp` |

**Dates**
- "Today" and week windows are computed in the **household timezone**: `household.timezone`,
  with the fallback used in `apps/web/src/kiosk/Calendar.tsx`.
- Never call Mealie's `/mealplans/today`.

**Web**
- `MealieUnavailable` → "Can't reach Mealie right now."
- `MealieAuthFailed` → "Mealie stopped accepting Waffled's token. An admin can reconnect it
  in Settings → Mealie."
- `MealieNoShoppingList` → "Choose a shopping list in Settings → Mealie."
- Each error state has a Retry button. Today cards collapse to one muted line instead.
- New bus topic `'mealie'`. Emit it after every Mealie write and connection change.

**Behaviour**
- With no connection, every existing screen must behave exactly as today. Existing tests
  must stay green untouched.
- Reuse the design system (`.modal-card`, `.field`, `apps/web/src/kiosk/components/`) per
  `apps/web/CLAUDE.md`. Nothing new in the design system unless nothing fits.

**Repo rules**
- TDD with the failing test first.
- Integration tests for the API use a fake Mealie server.
- Lean comments: WHY only, at most about 6 lines, and no backticks in SQL comments inside
  template literals.
- One commit or more per task.

**Spec deviation (ruling).** The spec says `presentHousehold` gains `mealie`. Instead, the
web reads `GET /api/mealie/connection`, which any member may call and which carries no
secret, once through `MealieProvider`.
- Why: `presentHousehold` is synchronous over a bare `households` row, and it's called from
  5 sites that use different queries.
- Cost if wrong: one extra request per app load.

**Second ruling: no `calendar-ai.ts` change.** Its `isPlannedMeal` feeds a per-event insight
card that only opens from a tapped event, and Task 8 hides meal-mirror events while
connected, so no stale meal can reach it. The same reasoning covers the EventDetail "View
recipe" link.
- Cost if wrong: one origin filter in `calendar-ai.ts`.

## Review Focus

1. **Token leakage.** A reviewer should grep every Mealie route response, and the error and
   log paths, for the token. A test asserts the raw token string is absent from connect,
   status and error bodies. (Task 1)
2. **Mealie down mid-session.** The kiosk keeps auto-refreshing. Every Mealie view must show
   the plain error with Retry, never an empty "no meals" or "list is empty" state that reads
   as real data. Tests render each view with a rejected `MealieUnavailable`. (Tasks 5–7)
3. **Timezone edge.** Near midnight, kiosk "Tonight" must use the household timezone date,
   not UTC or the Mealie server date. A test pins a clock at 23:30 America/Chicago, which is
   the next UTC day. (Task 5)
4. **Optimistic check-off reverting.** A failed PATCH must restore the item and show an
   inline error. A second tap during flight must be ignored. (Task 7)
5. **Disconnected households unchanged.** The swap points must render the built-in
   component when not connected. One test per swap point asserts the built-in component
   still renders. (Tasks 5–8)

**Interfaces:**
- Produces:
  - **Errors:** `class MealieError extends Error { statusCode }`, plus factories
    `mealieUnavailable()`, `mealieAuthFailed()`, `mealieNotConnected()` and
    `mealieNoShoppingList()`. Each sets `name` to the code in Global Constraints.
  - **Connection:** `getConnection(householdId): Promise<MealieConn | null>`, where
    `MealieConn = { baseUrl, publicUrl, token, shoppingListId, shoppingListName,
    mealieVersion }`, with the token decrypted.
  - **Required connection:** `requireConnection(householdId): Promise<MealieConn>`, which
    throws 409 when there's none.
  - **Client:** `mealieFetch<T>(conn: {baseUrl, token}, path: string, init?: {method?, body?}):

    for 204.
  - **Images:** `mealieFetchRaw(conn, path): Promise<Response>` for the image proxy.
  - **URLs:** `normalizeBaseUrl(raw: string): string` throws 400 `InvalidMealieUrl` on non
    http(s), embedded credentials or an unparsable value, and strips trailing slashes.
  - **Fake server:** `startFakeMealie(): Promise<{ url, token, state, close }>`.
    - It is a node `http` server on port 0.
    - `state` holds mutable `version`, `recipes`, `mealplans`, `lists`, `items`, plus a
      `requests` log of `{method, path, body, auth}` and a `down` switch that destroys
      sockets.
    - It answers the endpoints in the spec table, and 401 when the Bearer token ≠ `token`.
